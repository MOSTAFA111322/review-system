# تقرير قبول المستخدم النهائي قبل النشر

**تاريخ التحقق:** 15 أغسطس 2026  
**النظام:** نظام المراجعة المبسط  
**حالة البناء:** فحص TypeScript ناجح، و**39 اختبارًا ناجحًا ضمن 17 ملف اختبار**.  
**نطاق التقرير:** لا يضيف هذا التقرير ميزات جديدة؛ بل يثبت ما اختُبر فعليًا، ويصنف ما لم يكتمل اختباره أو تنفيذه بوضوح.

## منهجية التحقق

أُجري سيناريو قبول متكامل من خلال واجهات النظام الفعلية مع بيانات مؤقتة ذات بادئة `UAT`، شملت سنة مالية وهويات وصول وموظفين وأنواع عمليات وحالات وانتقالات ومراجعات وقيم حقول مخصصة. غطى السيناريو الإنشاء والتعديل والتكليف والبحث والفلاتر والفرز والترقيم والتعليقات والانتقالات والحذف المنطقي والاستعادة والتحليلات والعزل السنوي والصلاحيات، وكذلك رفع PDF وصورة PNG وملف Excel وتنزيل كل منها من رابط وصول موقّع. أزيلت بيانات القبول بعد كل تشغيل، ثم تحقق فحص قرائي مستقل من عدم بقاء سنوات أو مستخدمين أو موظفين أو مراجعات أو مرفقات مؤقتة.

كما أجريت معاينات واقعية للواجهات التشغيلية على سطح المكتب وعلى عرض هاتف **375 بكسل**، شملت لوحة المراجعات والتفاصيل والمحرر والإعدادات وDashboard والتقارير. أما تبديل الحسابات عبر متصفح واحد لكل الأدوار فلم ينفذ يدويًا؛ عوضًا عن ذلك نُفذت مصفوفة الصلاحيات والعزل عبر API الفعلي بهويات مؤقتة مستقلة، وهو دليل قوي على حواجز الخادم لكنه لا يغني عن مرور يدوي متعدد الحسابات قبل الإطلاق الإنتاجي.

## تحقق تصحيح مسار الإدارة

عولج الخلل الذي كان يجعل صفحة **المستخدمين والأدوار** وسجل تسجيل الدخول يظهران خارج غلاف لوحة التحكم. أصبحت الصفحة تعرض القائمة الجانبية وبطاقة الحساب بصورة صحيحة ضمن المسار `/users`، وظهر الاسم والدور للحساب الفعلي الحالي (**مدير النظام**) مع سجل الدخول. أضيف اختبارا انحدار مصدرّيان يثبتان تغليف صفحة الإدارة بـ `DashboardLayout` ووجود مدخل الحساب وتسجيل الخروج في الغلاف. اجتازت مجموعة الاختبارات الكاملة بعد التصحيح، بما فيها مصفوفة الصلاحيات الحية واختبار مسح Cookie تسجيل الخروج.

| بند التحقق بعد الإصلاح | النتيجة | الدليل |
|---|---|---|
| غلاف صفحة `/users` | PASS | ظهور القائمة الجانبية وبطاقة الحساب وسجل الدخول داخل المسار الإداري في معاينة المتصفح. |
| هوية جلسة مدير النظام الحالية | PASS | ظهور الاسم والدور `مدير النظام` في واجهة الإدارة الفعلية. |
| وصول مدير النظام إلى الإعدادات | PASS | تحميل واجهة باني الحقول والمرجعيات ضمن جلسة OAuth الحالية. |
| انحدار الغلاف والحساب | PASS | `server/users.layout.regression.test.ts` نجح باختبارين. |
| تبديل الحسابات الفعلية للمراجع والموظف | NOT EXECUTED | لا تتوفر هويتا OAuth إضافيتان: فحص قاعدة البيانات أظهر حسابًا واحدًا فقط بدور `admin`، ولا توجد حسابات محفوظة بدوري المراجع أو الموظف للاختبار المتسلسل. |

## المشكلات الحرجة قبل النشر

1. **لا توجد ثغرة صلاحيات مثبتة أو عطل تشغيلي حرج مكتشف** في مسارات المراجعات والحالات والسنوات والأدوار التي اختُبرت عبر API.
2. لا توجد ثغرة صلاحيات أو خلل تخزين مثبت في قبول المرفقات؛ اجتاز رفع وتنزيل الأنواع الثلاثة والرفض غير المصرح به، مع عدم بقاء مراجع قبول في قاعدة البيانات.
3. لا يزال يلزم توفير وربط حسابي OAuth حقيقيين بدوري المراجع والموظف، ثم تنفيذ مرور تشغيلي موجز لكل منهما للتأكد من تدفق الواجهة والجلسة. فحص قاعدة البيانات الحالي أظهر حساب مدير نظام واحدًا فقط؛ تحقق حساب مدير النظام الحالي وواجهة الإدارة بعد الإصلاح، لكنه لا يثبت الحسابين الآخرين.

## مشكلات غير حرجة وميزات مؤجلة

| التصنيف | البند | الأثر |
|---|---|---|
| NON-CRITICAL | إظهار/بحث الحقول المخصصة في جدول المراجعات | الفيم موجودة وتُحفظ، لكن لا يمكن استخدامها كعمود أو مفتاح بحث من اللوحة. |
| NON-CRITICAL | سياسة SLA قابلة للتهيئة وتنبيهات مستقلة | يوجد تاريخ مستهدف ومؤشر تأخير، لكن لا يوجد محرك قواعد SLA كامل. |
| NON-CRITICAL | اختبار تاريخي واسع لتعطيل نوع/حالة على عدة سجلات | التصميم يحافظ على التاريخ، لكن يلزم توسيع إثبات القبول. |
| UX | المسار `/reviews` غير معرف | لا تستخدمه الروابط الداخلية، لكنه يعرض 404 عند إدخاله يدويًا. |
| UX | زر «تعديل بيانات المراجعة» في صفحة التفاصيل | تم تثبيته داخل بطاقة الحالة، ويظهر لصاحب صلاحية التعديل ويفتح المحرر بصورة واضحة على الهاتف وسطح المكتب. أزيل زر الترويسة من المصدر ومن وحدة التطوير المقدمة للمتصفح؛ أي أثر مرئي قديم في معاينة التطوير لا ينتمي إلى الوحدة الحالية. |

## قرار النشر

> **FIX BEFORE PUBLISH**

السبب المتبقي هو غياب مرور يدوي متعدد الأدوار عبر OAuth والواجهة، وليس وجود عطل برمجي أو فجوة في قبول المرفقات. لا يلزم إضافة ميزة جديدة: يلزم فقط تنفيذ هذا التحقق التشغيلي الموجز وتوثيقه. بعد ذلك، إذا اجتاز دون مشكلة، يصبح القرار **READY TO PUBLISH**.
