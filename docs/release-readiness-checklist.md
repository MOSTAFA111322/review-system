# قائمة فحص الجاهزية للإطلاق الرسمي

هذه القائمة هي بوابة قرار وليست ميزة تجميلية. لا يُعلن الإطلاق الرسمي إلا بعد تحقق البنود الحرجة أو توثيق قبول المخاطر من مالك النظام.

## بوابة القرار

| المجال | معيار PASS القابل للتحقق | الحالة الحالية |
|---|---|---|
| الوظائف الأساسية | إنشاء وتعديل ومتابعة المراجعات والمهام اليومية وسداد الإيجارات والتسويات والتقارير تعمل من الواجهة ومن API | PASS برمجيًا، ويُستكمل قبول المستخدم النهائي |
| الصلاحيات | كل إجراء إداري محمي في Backend، مع رفض مباشر للحساب غير المخول، وليس مجرد إخفاء الزر | PASS وفق اختبارات RBAC والقبول المنشور |
| الجلسات | عزل المستخدمين، الخروج، إعادة الدخول، وإبطال الجلسة بعد تعطيل الحساب أو تغيير كلمة المرور | PASS ضمن نطاق الاختبارات المنفذة |
| السنوات المالية | منع القراءة والكتابة خارج السنة المسندة ومنع الكتابة في السنة المغلقة | PASS وفق اختبارات العزل وحارس السنة |
| جودة البيانات | منع التكرار، التحقق من الحقول المرجعية، التحقق من Excel قبل الحفظ، وعدم حذف السجلات المستخدمة | PASS برمجيًا؛ يلزم اختبار عينة بيانات حقيقية قبل الإطلاق |
| التقارير | التقرير يعرض البيانات التفصيلية المطلوبة، وتعمل المعاينة والطباعة والتصدير، ولا تظهر إعدادات التقرير في النسخة المطبوعة | PASS وفق اختبارات التقارير الحالية |
| الأداء | `pnpm exec tsc --noEmit` ينجح، و`pnpm test -- --run` ينجح كاملًا، و`pnpm build` ينجح، ولا توجد أخطاء متصفح حرجة في المسارات الرئيسية | PASS: 24 ملفًا و81 اختبارًا ناجحًا بعد عزل mock في RBAC، وTypeScript والبناء الإنتاجي ناجحان |
| Heartbeat | تنفيذ منشور بحالة `success` وHTTP 200 بعد آخر تعديل، دون timeout أو تكرار إشعارات | HOLD مؤقتًا حتى فحص تشغيل 24 أغسطس بعد 09:00 UTC؛ آخر تشغيل 23 أغسطس success وHTTP 200، مع timeout تاريخي في 21 أغسطس |
| النسخ الاحتياطي | وجود نسخة احتياطية قبل الإطلاق، ومعرفة مكانها ومالكها، واختبار قابلية القراءة والاستعادة على نسخة غير إنتاجية | HOLD حتى يعتمد الإجراء ويُختبر |
| Windows المحلي | تشغيل فعلي على جهاز Windows دون إنترنت وفق نطاق واضح للبيانات والمزامنة | HOLD؛ لم يُختبر داخل بيئة Linux الحالية |
| الأمن التشغيلي | استخدام HTTPS، أسرار خارج الشيفرة، حسابات منفصلة، أقل صلاحية ممكنة، وعدم مشاركة كلمات المرور | يجب تأكيده في بيئة التشغيل النهائية |
| خطة التراجع | معرفة إصدار checkpoint السابق وطريقة العودة إليه وتحديد مسؤول القرار | PASS من جهة checkpoint؛ يلزم اعتماد الإجراء تشغيليًا |
| قبول المستخدمين | يمر المدير والمراجع والموظف بالسيناريوهات اليومية، ويؤكد مالك النظام صحة التقارير والبيانات | يتطلب توقيع قبول تشغيلي |

## معايير الإطلاق

يكون القرار **READY TO PUBLISH** عندما تكون كل البنود الحرجة التالية بحالة PASS: الصلاحيات، الجلسات، عزل السنوات، سلامة البيانات، الاختبارات والبناء، Heartbeat بعد آخر تعديل، النسخ الاحتياطي، وخطة التراجع. أما اختبار Windows المحلي فهو شرط لمسار Windows فقط، وليس شرطًا لإطلاق نسخة الويب إذا كان هذا المسار خارج نطاق المرحلة.

يكون القرار **HOLD** عند وجود `timeout` أو `failed` في Heartbeat الأخير، أو فشل في Backend Authorization، أو عدم وجود نسخة احتياطية قابلة للتحقق، أو وجود خطأ يمنع إدخال البيانات أو استخراج التقارير. لا تُعد التحذيرات غير الحرجة في البناء وحدها سببًا كافيًا لحجب الإطلاق، لكن يجب توثيقها ومراقبتها.

## دليل القبول المطلوب

يُحفظ لكل بند رابط أو سجل أو لقطة شاشة مؤرخة. لا تُستخدم بيانات مراجعات أو مستخدمين وهمية في تقرير الإنتاج، ولا تُعتبر لقطة الواجهة وحدها دليلًا على الصلاحيات؛ الدليل الحاسم للصلاحيات هو استجابة Backend المرفوضة للحساب غير المخول.

## القرار الحالي

**HOLD تشغيليًا** إلى حين فحص تشغيل Heartbeat المجدول في 24 أغسطس بعد 09:00 UTC، واعتماد النسخ الاحتياطي وقبول المستخدم النهائي. النسخة البرمجية الحالية اجتازت فحوص TypeScript وVitest والبناء: 24 ملفًا و81 اختبارًا، لكن النجاح البرمجي وحده لا يساوي الجاهزية التشغيلية الكاملة. مسار Windows يبقى مفتوحًا فقط إذا كان ضمن نطاق الإطلاق المحلي.
