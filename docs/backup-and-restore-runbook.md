# إجراء النسخ الاحتياطي والاستعادة التشغيلي

## الغرض

هذا الإجراء يحمي بيانات المراجعات والمهام اليومية ومتابعة الإيجارات والتسويات قبل الإطلاق أو أي تغيير حساس. لا ينفذ النظام حذفًا أو استعادة تلقائية من داخل الواجهة؛ الاستعادة مسؤولية مالك قاعدة البيانات أو مسؤول التشغيل المعتمد.

## قبل الإطلاق

ينبغي لمسؤول التشغيل أخذ نسخة احتياطية كاملة من قاعدة MySQL/TiDB باستخدام أداة مزود قاعدة البيانات المعتمدة، وحفظها في موقع مشفر خارج جهاز المستخدم، مع تسجيل وقت النسخة واسم الإصدار المنشور ومالك الإجراء. يجب عدم وضع ملف النسخة في مستودع Git أو مجلد الواجهة أو مشاركته عبر المحادثة.

تُسمى النسخة وفق النمط التالي:

`review-system_<UTC-date>_<checkpoint-version>.sql.gz`

ويُسجل معها: التاريخ والوقت بتوقيت UTC، إصدار checkpoint، بيئة المصدر، حجم الملف، وقيمة hash مثل SHA-256. لا تُعتبر النسخة صالحة قبل التحقق من إمكانية قراءتها وفك ضغطها.

## اختبار الاستعادة قبل الإطلاق الرسمي

تُستعاد النسخة في قاعدة غير إنتاجية منفصلة. بعد الاستعادة، يتحقق المسؤول من عدد الجداول، وجود سنة مالية، وجود مستخدمين وأدوار، ظهور المراجعات والمهام، وجود سجلات متابعة السداد والتسويات، وإمكان تشغيل التقرير والتصدير. لا تُجرى تجربة الاستعادة فوق قاعدة الإنتاج.

يُنفذ اختبار عينة قراءة فقط، ثم تُشغّل اختبارات التطبيق والبناء. إذا فشلت الاستعادة أو ظهرت بيانات ناقصة، تُرفض النسخة ويُؤخذ Backup جديد قبل الإطلاق.

## قبل أي تغيير حساس

يحفظ المسؤول checkpoint برقم الإصدار، يوقف أي عملية كتابة غير ضرورية، يأخذ نسخة جديدة، ثم يطبق التغيير. لا تُنفذ أوامر `DROP`, `TRUNCATE`, أو حذف جماعي على الإنتاج ضمن إجراءات القبول.

## الاستعادة عند الحادث

يُعلن المسؤول حالة الحادث ويوقف الكتابة غير الضرورية، ثم يحدد آخر نسخة سليمة وآخر checkpoint معروف. قبل الاستعادة يجب حفظ نسخة من الحالة الحالية للتحقيق. تُستعاد البيانات في بيئة منفصلة أولًا، ويُراجع الفرق، ثم يقرر مالك النظام الاستعادة إلى الإنتاج وفق سياسة قاعدة البيانات ومزود الاستضافة.

بعد الاستعادة، يُتحقق من الصلاحيات والجلسات والسنوات المالية والتقارير وسجل النشاط، ثم يُعاد تشغيل قبول الأدوار الثلاثة دون تعديل بيانات العمل. تُوثق النتيجة والوقت والنسخة المستخدمة وأي فقد بيانات محتمل.

## معيار PASS

يُغلق بند النسخ الاحتياطي عندما توجد نسخة مشفرة قابلة للقراءة، ويكون hash مسجلًا، وتنجح استعادة عينة إلى بيئة غير إنتاجية، ويعرف مالك النظام مكان النسخة ومسؤول الاستعادة. وجود تعليمات مكتوبة وحده لا يكفي لإغلاق الاختبار العملي.

## الحالة الحالية

هذا الملف يحدد الإجراء والمسؤوليات، لكنه لا يثبت أن نسخة إنتاجية أُخذت أو أُعيدت. يجب تحديث سجل التسليم بعد تنفيذ الاختبار الفعلي من مسؤول قاعدة البيانات.
