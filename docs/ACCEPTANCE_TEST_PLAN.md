# خطة اختبار القبول التشغيلي

هذه الخطة مخصصة للتشغيل بعد أن يهيئ مدير النظام السنة المالية والأنواع والحالات، وتستخدم فقط بيانات العمل الحقيقية المصرح بها. لا ينشئ المشروع تلقائيًا مراجعات أو تقييمات أو مؤشرات أداء مصطنعة لأغراض الاختبار.

| السيناريو | الدور | النتيجة المتوقعة |
|---:|---|---|
| 1 | مدير النظام | يهيئ النظام وينشئ سنة مالية مفتوحة ويحددها كسنة حالية. |
| 2 | مدير النظام | ينشئ نوع عملية وحالات المراجع والموظف وقاعدة انتقال مسموحة. |
| 3 | مراجع | ينشئ مراجعة حقيقية؛ يظهر رقم داخلي تلقائي، ولا يمكن اختيار مرجعيات معطلة. |
| 4 | موظف مكلّف | يرى المراجعة المسندة إليه فقط، ويستطيع تحديث حالة الموظف ضمن انتقال مسموح وإضافة تعليق/مرفق. |
| 5 | مراجع | يراجع الرد ويغيّر حالة المراجع ضمن الصلاحية، ويظهر الحدث في سجل النشاط. |
| 6 | مدير | يراجع Dashboard والتقارير؛ يجب أن تتطابق الأرقام مع المراجعات الحقيقية في السنة المحددة. |
| 7 | مدير النظام | يغلق السنة ثم يتحقق من رفض كل عمليات الكتابة في المراجعات والتعليقات والمرفقات والتغييرات. |
| 8 | مدير النظام | يستعيد مراجعة محذوفة منطقيًا في سنة مفتوحة، ويتحقق من ظهور سجل التدقيق. |
| 9 | مدير النظام | يصدّر تقرير السنة إلى CSV وExcel، ويقارن عدد الصفوف بنتائج الفلترة المعروضة. |
| 10 | جميع الأدوار | يفتح الواجهة على الجوال ويتحقق من ترتيب البطاقات، حالات التحميل/الفراغ، وقابلية الوصول إلى الإجراءات المتاحة فقط. |

## التحقق الآلي المنفذ

- تم تنفيذ فحص الأنواع باستخدام `pnpm check` بنجاح.
- تم تنفيذ 11 اختبار Vitest بنجاح، تغطي حراس RBAC، وعزل السنة، وحماية API للمستخدم المجهول، وتسجيل الخروج، وحالات التحليلات الخالية.
- لم تُشغّل اختبارات تكامل تعتمد على إدخال بيانات مراجعات مصطنعة في قاعدة البيانات؛ لذلك تبقى السيناريوهات التشغيلية أعلاه خطوة قبول مطلوبة عند توفر بيانات العمل الحقيقية والأدوار الفعلية.
